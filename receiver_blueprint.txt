=========================================================
          RECTRIX PC RECEIVER BLUEPRINT
=========================================================

1. OVERVIEW
This document outlines the protocol required to build a PC 
receiver for the Rectrix mobile gamepad app. The receiver 
must act as a UDP server that generates a connection QR code, 
listens for incoming UDP packets, validates them via a pairing 
code, and translates the decoded values into virtual gamepad inputs.

---------------------------------------------------------
2. NETWORK CONFIGURATION
---------------------------------------------------------
- Protocol: UDP (IPv4)
- Host: 0.0.0.0 (Listen on all network interfaces)
- Port: 5005
- Endianness: Big-Endian (Network Byte Order)

---------------------------------------------------------
3. THE PAIRING PROCESS (QR CODE)
---------------------------------------------------------
To pair the mobile app to the PC, the receiver must generate 
a QR code and display it on the screen.

1. IP Address: The receiver must automatically resolve the PC's 
   active local IPv4 address (e.g., 192.168.x.x).
2. Pairing Code: Generate a random integer between 10000 and 65534.
3. Payload: Create a JSON string with the following exact keys:
   {
     "ip": "192.168.1.15",
     "code": 48291,
     "name": "MY-GAMING-PC"
   }
4. Encode this JSON string into a QR code for the mobile app to scan.

---------------------------------------------------------
4. PACKET STRUCTURE & DECODING
---------------------------------------------------------
All incoming packets MUST be exactly 32 bytes in length.
If a packet is >32 or <32 bytes, it is malformed and MUST be dropped.

The 32 raw bytes must be decoded into an array of 16 unsigned 
16-bit integers (UInt16). Every integer maps to a specific input:

[INDEX] - [INPUT TYPE]
  0     - Left Joystick X (0 to 65534, Center is 32767)
  1     - Left Joystick Y (0 to 65534, Center is 32767)
  2     - Left Trigger (0 to 65534, 0 is unpressed)
  3     - Left Bumper (0 or 1)
  4     - D-Pad (0=None, 1=Up, 2=Down, 3=Right, 4=Left)
  5     - Right Joystick X (0 to 65534, Center is 32767)
  6     - Right Joystick Y (0 to 65534, Center is 32767)
  7     - Right Trigger (0 to 65534, 0 is unpressed)
  8     - Right Bumper (0 or 1)
  9     - Face Buttons (0=None, 1=A, 2=B, 3=X, 4=Y)
 10     - Left Stick Click / L3 (0 or 1)
 11     - Right Stick Click / R3 (0 or 1)
 12     - Select / Back (0 or 1)
 13     - Start / Menu (0 or 1)
 14     - Pairing Code (Matches the code from the QR payload)
 15     - Phone Session ID (Unique 5-digit ID generated by the phone)

---------------------------------------------------------
5. PACKET LIFECYCLE & TYPES
---------------------------------------------------------
The receiver will encounter 3 distinct types of valid packets.

A. The Pairing Burst (Connection Initialization)
   When a user opens the gamepad screen, the app immediately sends 
   a burst of 4 packets to announce its presence.
   - Signature: Indices 0 through 14 will ALL equal the Pairing Code.
   - Index 15 will contain the Phone Session ID.
   - Action: The receiver should register this Phone Session ID as 
     an active connected device.

B. Standard Input Data (Gameplay)
   These are the high-frequency packets containing actual finger movements.
   - Signature: Index 14 will equal the Pairing Code.
   - Action: Check if Index 15 matches a known connected Phone Session ID.
     If it does, pass Indices 0-13 to the virtual gamepad driver (e.g., ViGEmBus).

C. The Release Packet (Finger Lift)
   Because UDP does not guarantee delivery, the app sends special 
   "release" packets when the user removes all fingers from the screen 
   to prevent the character from getting stuck walking or spinning.
   - Signature: Indices 0 through 14 will ALL equal 65535.
   - Index 15 will contain the Phone Session ID.
   - Action: Immediately set all joysticks to center, zero all triggers, 
     and unpress all buttons for the associated virtual gamepad.

---------------------------------------------------------
6. ERROR HANDLING & SECURITY
---------------------------------------------------------
- Buffer Constraints: Read exactly 32 bytes.
- Invalid Code: If a Standard Packet arrives where Index 14 does NOT 
  match the generated Pairing Code, drop it immediately.
- Unknown Phone ID: If you wish to support multiple local controllers, 
  keep track of unique Phone Session IDs (Index 15). If a packet arrives 
  from an unrecognized ID but contains the correct pairing code, 
  accept it and spawn a new virtual gamepad.

---------------------------------------------------------
7. VIRTUAL GAMEPAD MAPPING (RECOMMENDATIONS)
---------------------------------------------------------
- The app outputs Left/Right stick values from 0 to 65534.
  (Center is exactly 32767).
- Many virtual controller drivers (like Xbox 360 emulation) expect 
  joystick axes as Signed 16-bit integers (-32768 to 32767). 
  You may need to translate the app's output mathematically:
  Mapped_Axis = App_Axis - 32767
- Triggers map perfectly from 0 to 255. You can scale the app's 
  0-65534 trigger output by dividing by 256.
